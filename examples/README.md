# UFrame 轻量游戏示例

运行项目会进入 `example_browser.tscn`。按 `1 / 2 / 3 / 4`、横向滚动卡片或直接点击卡片进入四个示例；示例内按 `Esc` 返回。全部画面由 Godot 原生节点和 Canvas 绘制生成，没有图片、字体、音频或第三方依赖。

> 文档定位：本文件只说明示例入口、操作和当前展示内容。整体职责与依赖见 [ARCHITECTURE.md](../ARCHITECTURE.md)，插件公共用法见 [插件 README](../addons/uframe/README.md)。

## 应该怎样阅读这些示例

示例遵循“场景树就是架构说明”的原则：

- 长期存在、需要 Inspector 配置的实体、组件、状态、碰撞体、对象池和 UI 容器全部写在 `.tscn`；
- 物品和掉落表等静态数据写在 `.tres`；
- 只有敌人、子弹、粒子、64 个同构格子、洗牌后的 104 张 Card View、拖拽预览和 Tween 等数量、身份或生命周期取决于运行时的内容才动态生成；
- 脚本主要负责连接信号、注入运行时目标和编排流程，不在 `_ready()` 中重新搭建整棵场景树。

这是以 Godot 节点组合为基础、向 ECS 思维铺垫的方式，不是额外实现一套数据导向 ECS。阅读时建议同时打开主玩法场景和对应的实体场景。

## 1. 生存竞技场

目录：`res://examples/arena/`

操作：WASD 或手柄左摇杆移动，角色自动瞄准与射击。

展示内容：

- `arena_demo.tscn` 直接摆放 Player、Enemy/Bullet/Effect 三个对象池、Camera 和 HUD；
- EnemyPool、BulletPool 与 EffectPool 都配置容量上限；满载时统一结束并复用最早活跃实例；
- `arena_player.tscn` 在直属 `BehaviorManager` 下静态挂载真实的 Movement 行为；WASD、物理移动、边界限制和按位移扬尘都由该行为负责；
- `arena_player.tscn` 与 `arena_enemy.tscn` 把 Health、Team、Hitbox、Hurtbox 和碰撞形状作为实体子组件；
- `arena_bullet.tscn` 使用“Node2D 实体根 + HitboxComponent 子节点”，移动与伤害职责不混在同一个类中；
- 敌人接触攻击完整经过 `ContactHitbox → Team → Hurtbox → Health`，没有绕过组件直接扣血；
- `UFramePool` 复用敌人、子弹和粒子爆发；闲置根节点停用后，Godot 根据后代默认的 `Disable Mode = Remove` 自动移出碰撞组件；
- 玩家扬尘由实际移动距离、方向和速度触发；
- 命中闪白、实际击退、死亡爆散、炮口拖尾和 Camera2D trauma；
- 控制器缓存敌人引用，不在每次射击时重新分配 Group 数组。

## 2. 单屏平台跳跃

目录：`res://examples/platformer/`

操作：A / D 或手柄移动；短按空格低跳，长按高跳。

展示内容：

- `platformer_demo.tscn` 显式包含全部平台、Goal、Player、EffectPool、Camera 和 HUD；
- EffectPool 设置总量上限并开启最早实例复用，连续移动与落地不会因特效峰值临时创建新节点；
- `platformer_player.tscn` 的直属 `StateMachine` 下挂载 Idle、Run、Air 三个状态节点；
- 三个状态脚本真正负责各自的速度、跳跃、重力、`move_and_slide()` 和转换，不只是给 HUD 提供状态名称；
- InputMap 输入，支持重映射和手柄；
- 本示例依赖已启用的 `UFrameInput` 模块，用它实现跳跃输入缓冲；土狼时间由玩家脚本维护为 0.11 秒；
- 长按窗口收紧为 0.085 秒；松开会截断上升速度；
- 走路粒子按真实位移产生，起跳和落地效果受水平速度与冲击速度影响；
- 玩家视觉独立拉伸、压扁、倾斜，不缩放碰撞体；
- 旗帜 `Area2D` 是唯一终点，无法沿地面绕过；
- 远山、云、月亮、平台高光和成功彩带均由原生绘制生成。

## 3. 掉落与背包工坊

目录：`res://examples/loot/`

操作：拖拽格子移动、合并或交换；右键拿 1 个；Ctrl + 右键拿一半；左键放下鼠标物品。

点击抽取按钮进行一次掉落，按住 Shift 点击可抽取十次，展示 `LootTable.roll_multi()` 合并结果后通过 `Inventory.add_items()` 一次提交背包变化。

展示内容：

- `loot_demo.tscn` 直接包含 `Player/InventoryComponent`、全部固定 UI 和 `SlotGrid` 挂载点；
- `InventoryComponent` 的 64 格容量与 64/16/1 堆叠规则都能在 Inspector 中查看；
- 九个 `LootDemoItemData .tres` 展示如何继承 `UFrameResourceData` 添加项目专属字段；
- `demo_loot_table.tres` 保存九条掉落配置；运行时只由调用者持有独立保底计数；
- 单一 `UFrameInventory` 提供位置、拆分、合并和分类整理，格子 View 不包含第二套背包规则；
- 64 个同构格子从 `inventory_slot_button.tscn` 实例化，修改模板即可统一修改显示；
- 默认预置零散物品，进入场景即可体验核心交互；
- 64 个格子只在对应 `slot_changed` 时局部刷新，不再整体重建 StyleBox；
- 原生绘制金币、宝石、药水、炸弹、剑盾与王冠图标；
- 返回、保存和读取前会安全放回鼠标物品，背包已满时阻止离开；
- `UFrameRunData` 子类与 `UFrameSave` 的中断恢复存档。

## 4. 蜘蛛纸牌

目录：`res://examples/spider/`

操作：点击标题下方的“单色 / 双色 / 四色”或按 `1 / 2 / 4` 切换难度（会开始新牌局）；左键拖拽一张牌或合法牌组，右键自动移动；点击“发牌”；按 `H` 获取提示；使用“撤销”和“重开”按钮辅助操作。

玩法规则：

- 三档难度都使用 104 张牌：单色每个点数 8 张，双色中每种花色每个点数 4 张，四色中每种花色每个点数 2 张；开局分到固定 10 列，其余 50 张保留在牌库；
- 单张牌只需按点数接龙，因此可以跨花色放到点数恰好大 1 的牌下面；空列可以接收任意一张牌或一组合法牌；
- 多张牌整体拖动时，牌组必须全部正面朝上、同花色且点数连续降序，例如同为红桃的 `9 → 8 → 7`；
- 右键某张翻开的牌会自动移动“该牌到列顶”的完整合法后缀：优先接同花色的上一点数，其次接其他花色的上一点数，最后使用最左侧空列；例如黑桃 `4 → 3 → 2 → A` 会先找黑桃 `5`，没有时再找其他花色的 `5`；
- 牌库共有 5 次发牌机会，每次向 10 列各发 1 张；存在空列时不能发牌，避免产生不可恢复的空洞布局；
- 同一列出现同花色的完整 `K → Q → ... → 2 → A` 后会自动收为一组；完成 8 组即获胜；
- 撤销会恢复上一次移动或发牌之前的完整局面，包括翻牌和自动收组，不只把最上方一张牌移回去。

结构与性能展示：

- `spider_demo.tscn` 直接摆放难度按钮、Tableau、Completed、CardLayer、DragLayer、FeedbackOverlay、牌库 HUD 和固定的 `Column01` 到 `Column10`；稳定的交互与列结构不在 `_ready()` 中临时创建；根节点还可通过 `Default Suit Count` 设置默认难度；
- 104 张牌的身份和位置由洗牌结果决定，所以从同一个 `spider_card.tscn` Card View 模板在运行时实例化；这属于重复 View，不是在代码里隐藏框架组件；
- 纯规则模型只保存牌局数据并判断花色分布、移动、右键目标优先级、发牌、空列、完成序列和撤销；Card View 只汇报左/右键意图并负责花色显示、绘制和 Tween，两者不会各自维护一套规则；牌背始终一致，不会泄露暗牌花色；
- 拖拽时只把当前牌组暂时移入 DragLayer，完成后仍回到统一 CardLayer，避免不断创建和销毁显示节点；
- 合法落牌只重排来源列与目标列；新局、发牌和撤销才同步十列，避免一次局部动作写回整副牌；
- 发牌的十张牌共享一个入场调度 Tween；翻牌使用 CanvasItem 缩放复用既有绘制命令，不会在动画每一帧重建复杂牌面；
- FeedbackOverlay 集中绘制薄荷色蛛丝、琥珀色完成光环和少量粒子；粒子总量有上限并以 30 Hz 更新，没有效果时关闭自身 `_process()`；
- 每张 Card View 都没有常驻 `_process()`；相同交互状态和零变化悬停不会创建 Tween，被覆盖的牌只绘制实际露出的顶部条，只有列顶牌绘制完整牌面；
- 长列会根据可用高度压缩纵向间距，保证 960×640 下十列与操作栏始终可见。

## 示例边界

- `examples/common/` 只包含示例主题、卡片/格子等 View 场景、动态背景和可池化粒子，不会随插件被宿主运行时加载；
- 示例项目使用 GL Compatibility，降低纯 2D 展示的启动和显卡要求；
- 每个示例退出后，其场景节点全部释放；没有新增全局单例；
- 示例负责实体组合与“看起来怎样”，UFrame 公共层只负责可复用规则；
- 测试脚本可以用 `.new()` 构造最小夹具，但正式示例不会用这种方式隐藏静态组件结构。
